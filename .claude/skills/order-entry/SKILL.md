# 图片录单 SOP

卖家发图片 → Claude 提取订单信息 → 卖家确认 → 调接口写入 → 回报结果。
**任何一单都必须经卖家明确确认后才写库。**

## 0. 隐私（最高优先级）

- 仓库 `RexingRui/crab` 是**公开**的。图片、提取出来的订单数据、CSV、token
  一律**不进 Git**，不写进任何会被提交的文件。
- 工作文件放会话的 scratchpad 目录；`import/*.csv` 虽已被 `.gitignore` 忽略，也不要放真实数据。
- 回报给卖家时可以写完整信息；写进日志/提交信息/PR 时手机号打码。

## 1. 前置检查（每个会话开始时做一次）

1. 向卖家要两样：`CRAB_API`（备案前为 `http://<服务器IP>`，走 Caddy 80 端口的 IP 站点；
   备案后为 `https://<域名>`）和管理员 token。只放在 shell 环境变量里。
2. 检查 token 有效期：token 是 `base64url(payload).sig`，payload 里 `exp` 是 unix 秒。
   剩余不足 1 小时就先请卖家重签（服务器上用 `scripts/admin-api.sh` 同样的方式签）。
3. `curl $CRAB_API/healthz` 返回 `code:0`。
4. `GET /api/specs?all=1` 拉当前价目表，**只认 `enabled:true` 的规格**。价目表每季会变，不要沿用记忆里的价格。
   规格按只计价：一档 = 性别 + 克重 + 品相（正常 / 残蟹），`unit_price_milli` 是单只价（厘，0.001 元），
   `title` 形如「母3两」「公4两(残)」。没有「盒」：「8 只 189」只是报价方式。

> 云环境出口只放行 80/443，后端 8080 直连不通，所以必须走 80/443。

## 2. 从图片提取

每单字段：

| 字段 | 规则 |
|---|---|
| 收货人 / 手机 / 地址 | **原样抄**，不纠错、不补全。看不清的字标 `？` 并列入「待确认」 |
| 微信昵称 / 备注 | 图片里有就填 |
| 规格与只数 | 映射到启用中的规格（写 `title`，如「母3两」）。**数量一律换算成只**：「两盒」= 16 只。没写公母**默认母蟹**；写法对不上（如只写「269 的两盒」）时按价格 / 克重推断并列入「待确认」 |
| 单只价 | 金额 = 只数 × 单只价，向上取整到元。图片里的价和这个算法一致就不填；不一致说明是临时改价，填 `单只价 = 总价 ÷ 只数`（元，最多三位小数，向下取到厘，进位后正好落回总价），并在确认表里标出 |
| 运费 / 优惠 | 图片明确写了才填。买家补的运费计入应收；快递原价 / 实际花的钱（用券后）另记，只给卖家看 |
| 已收款 | **只有看到付款凭证或明确的「已付」才填**，同时记付款方式；拿不准一律不填 |
| 期望发货日 | 明确写了才填，格式 `YYYY-MM-DD`，年份默认当年 |

不确定的地方宁可空着问，也不要猜。一张图有多单要拆开；多张图是同一单要合并；**两个包裹就是两单**。
付款人（微信联系人）记在 `wechat_nick` / `wechat_remark`，代下单时付款人和收件人不是同一个人。

## 3. 查重

逐单 `GET /api/orders?keyword=<手机号>&page_size=50`，库里已有同手机号的未取消订单时，
在确认表里标「库里已有 <订单号>」，由卖家决定是否仍要新建。

## 4. 与卖家确认

列一张表，每单一行：序号、收货人、手机、地址、明细（规格×数量，含改价）、运费、优惠、
**应收**（自己按 Σ数量×单价 + 运费 − 优惠 算好）、已收款、备注；
另列「待确认」清单（看不清的字、推断的规格、改价、重复）。
**等卖家明确回复确认（或给出修改）后才进入第 5 步。** 修改后重新出表再确认。

## 5. 写入

1. 在 scratchpad 里写导入文件，`ref` 用确认表里的序号。只建单 + 一笔收款用 CSV
   （`import/orders.template.csv` 的列）；要带收款时间、发货、运费、签收的历史单用 JSON。
   两种格式都见 `import/README.md`。
2. 批次名 `--batch` 用 `<MMDD><字母>`，如 `1006a`；同一天第二批用 `1006b`。
   **同一批重跑必须用同一个批次名**（幂等依赖它），新的一批必须换名字。
3. 预览：`python3 scripts/import-orders.py <csv> --batch <批次>`，
   核对预览里每单应收与确认表一致。不一致就停下查原因。
4. 写入：同一命令加 `--commit`。网络中断就原样重跑：已建的单按当前状态只补没做完的步骤，
   不会重复记收款。

## 6. 核对与回报

- 回报每单的订单号、应收、已收；有失败的单单独列出原因。
- `GET /api/stats/dashboard` 看今日新增单数是否对得上。
- 写完删掉 scratchpad 里的导入文件。

## 7. 录错了怎么办

| 情况 | 处理 |
|---|---|
| 收货信息/明细/运费/优惠错了 | 先 `GET /api/orders/{id}` 拿当前完整数据，改好后 `PUT /api/orders/{id}` **整单提交**（PUT 是全量覆盖，漏传的字段会被清空），带上 GET 到的 `updated_at` 做乐观锁 |
| 收款记错 | `POST /api/orders/{id}/payments` 记一笔**负数**冲掉，再记正确的；没有删除收款的接口 |
| 整单不该建 | 征得卖家同意后 `DELETE /api/orders/{id}`（软删除） |

所有修改、删除都要先告诉卖家要改哪单、改成什么，得到确认再动。
